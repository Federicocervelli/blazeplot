# BlazePlot v1.0.4

## Fixes

- **Modern CSS colors:** theme and series style colors in `oklch()`, `oklab()`, `lab()`, `lch()`, and `color()` spaces (`display-p3`, `rec2020`, `a98-rgb`, `prophoto-rgb`, `srgb-linear`, `xyz`, `xyz-d50`, `xyz-d65`) now render in that color instead of silently falling back to the default palette. This also fixes `var(--x)` references to such colors, so shadcn/ui and Tailwind CSS v4 tokens like `seriesColors: ["var(--chart-1)"]` and `gridColor: "var(--border)"` work. Colors outside the sRGB gamut are clipped per channel. Any other color syntax the browser understands is read back from a 1x1 canvas.
- **Invalid colors:** a color string the browser rejects now falls back to the default color instead of the chart root's inherited text color, and development builds log one warning per string naming the theme key or series style.
