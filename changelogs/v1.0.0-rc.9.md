# BlazePlot v1.0.0-rc.9

Ninth 1.0 release candidate, and the last planned breaking round before 1.0. The rendering engine is now just an option, the API got a consistency pass (names, units, types), defaults were made safe for real pages, and a performance pass cut startup and lifecycle costs. Install with `npm install blazeplot@rc`, and see the [0.x to 1.0 migration guide](https://github.com/Federicocervelli/blazeplot/blob/v1/docs/migrating-to-1.0.md) (changes 14 to 17 and the checklist cover this release).

## Breaking: rendering engines

- The default renderer is now `"auto"`: WebGL2 when available, Canvas 2D otherwise, quietly (`chart.rendererInfo.fallbackFrom` says when it fell back). Pass `renderer: "webgl2"` to keep the old throw.
- `blazeplot/renderers/canvas2d` and `blazeplot/renderers/shared` are removed. `webgl2Renderer`, `canvas2dRenderer`, `sharedRenderer`, `autoRenderer`, `createChartRenderContext`, `Canvas2DUnavailableError` and `ChartRenderContext` are root exports, and the option also takes the names (`renderer: "canvas2d"`, `"shared"`) with no import.
- `chart.renderer` reports `"shared"` instead of `"webgl2-shared"`; `ChartRendererKind` is gone (use `RendererName`). An unknown `renderer` value throws a `TypeError` listing the valid names.
- Canvas 2D is a stable engine: its feature set is covered by semver; pixel-level output between engines and releases is not.

## Breaking: API consistency

- `AxisControllerAxisOptions` is `AxisScaleOptions` and stable. Only the `CustomAxisScale` hook stays experimental.
- `screenshot({ dpr })` and `chart.resize(dpr)` take `pixelRatio`.
- `histogram()` is `histogramBins()` in `blazeplot/data` (use `HistogramDataset.from` for charts).
- Pixel-valued plugin options end in `Px`: text and title `offsetXPx` / `offsetYPx`; annotation `widthPx`, `borderWidthPx`, `radiusPx`, `strokeWidthPx`; crosshair `widthPx`, `markerSizePx`, `markerStrokeWidthPx`; navigator `heightPx`, `strokeWidthPx`, `handleWidthPx`, `handleHitWidthPx`, `marginPx`. Series `lineWidth` / `pointSize` are documented as CSS px and `barWidth` / `tickWidth` as data X units.
- Series configs are a discriminated union: a dataset, or a ring buffer with `capacity`. Wrong combinations (`addCandlestick({ capacity })`, `{ capacity, dataset }`, `{ xStep }` without `capacity`) are compile errors, and buffer options next to a `dataset` throw. `append`, `updateLast` and `updateAt` are typed by the dataset.
- Every `ChartTheme` colour accepts a CSS string or RGBA.
- `getSeriesState()` and `getFrameStats()` return readonly types.
- Removed the `rendererchange` event, which nothing emitted.

## Breaking: defaults

- `interactionsPlugin` `touchPan` defaults to `"two-finger"`: one finger scrolls the page, two fingers pan and pinch. Pass `touchPan: true` for one-finger chart pan. `wheelZoom` stays `true`.
- The chart root is a tab stop only when it has a description or plugins.
- Navigator value text uses the axis format, so time axes read as dates instead of epoch milliseconds.

## New

- Shorthands: `addLine`, `addArea`, `addScatter` and `addBar` accept `{ x, y }`; `addBar` accepts `{ values, binSize | binCount | thresholds, ... }`.
- `theme: "auto"` follows `prefers-color-scheme` and reacts to changes.
- `chart.rendererInfo`, read-only `ctx.renderer` for plugins, `autoRenderer({ shared })`, and an optional `preloadWebGL()` idle warm-up.
- Chart events `contextlost` and `contextrestored`.
- `messages` on `navigatorPlugin`, `annotationsPlugin` and `interactionsPlugin`, plus navigator `label` / `formatValueText`. The full list of localizable strings is in the accessibility guide.
- Experimental `ctx.unstable.createRenderSurface(canvas)`: plugin layers follow the chart's engine. The flame graph plugin uses it (no second WebGL context, joins the shared context, entry about 4.7 KB smaller).
- Clear errors for a missing target (`new Chart(null)`), and one-time development warnings for a zero-sized host and for a series added without `start()`.
- Concrete browser minimums (Chrome and Edge 93, Firefox 92, Safari 15.4), `package.json` `default` export conditions and `typesVersions`, so `require`, Jest, Vitest and `moduleResolution: node10` resolve every entry point.

## Fixes

- Annotation labels used the default serif font: `font` was set as an SVG attribute, which browsers ignore.
- Canvas 2D filled area series across gaps (non-finite Y) instead of breaking the fill.
- Hover is resolved in the pointer handler, so the tooltip and crosshair update without waiting for the next animation frame.

## Performance

Measured on a real GPU against uPlot and Chart.js with the new fair, 18-scenario comparison suite (`benchmarks/latest.md`, with a before-the-pass baseline kept for comparison):

- Pan, stream, area, scatter, bar and dual-axis frame rates already led and improved further (for example 1M-point pan 993 to 1090 fps; Canvas 2D 622 to 831). Canvas 2D now also beats uPlot on 1M pan, multi-series and bars.
- Startup: time to first frame at 100k points 6.7 to 4.5 ms (WebGL) and 4.4 to 2.8 ms (Canvas 2D). Shader programs compile in parallel from `addSeries`; the min/max index is built lazily and queried without allocating.
- Lifecycle: mount/destroy 4.8 to about 1.3 ms through a short-lived warm canvas pool (a disposed chart parks its context for 2 seconds; the context is released up to 2 seconds after the last chart), 50 charts ready 42 to 21 ms and JS heap 43 to 7 MiB.
- Per-chart cost: axis labels are diffed instead of rewritten, titles are created on demand, and vertex scratch buffers are shared across charts.
- Known remaining gaps against uPlot: first-frame time at small sizes (a WebGL context creation round trip), hover latency (0.39 vs 0.22 ms) and 50-chart destroy time.

## Bundle

- The chart-only import graph is about 207 KB raw (Canvas 2D and the shared context ship with the default renderer; tree-shaking verified: one plugin pulls in no others). The shorthands moved `StaticDataset` and `HistogramDataset` behind `Chart`.

## Tooling

- One behavior contract suite runs against all three engines; the UI suites run on each engine; the visual suite compares Canvas 2D and shared output with WebGL2 (`scripts/cross-engine.ts`); a Canvas 2D performance gate has its own thresholds.
- Browser suites are sharded: a PR finishes in about 2 minutes, and docs-only PRs skip the engine suites.
- The source tree is layered and enforced (`bun run test:imports`): no import cycles, plugins in `src/plugins/<name>/`, no file over about 900 lines, and former `@internal` members reached through an internal accessor.
- Coverage floors were ratcheted (core 98%, plugins 97%) with per-file floors for the painter, screenshot, pickers and resampling.
