# BlazePlot v1.0.0-rc.9

Ninth 1.0 release candidate. Rendering engines are now one coherent layer: WebGL2, Canvas 2D, and the shared WebGL2 context are selected with `ChartOptions.renderer`, the default falls back to Canvas 2D, and the optional renderer entry points are gone. Install with `npm install blazeplot@rc`.

## Breaking

- The default renderer is now `"auto"`: WebGL2 when it is available, Canvas 2D otherwise, quietly (`chart.rendererInfo.fallbackFrom` says when it fell back). `new Chart(...)` used to throw `WebGL2UnavailableError` without WebGL2; pass `renderer: "webgl2"` to keep that.
- `blazeplot/renderers/canvas2d` and `blazeplot/renderers/shared` are removed. `webgl2Renderer`, `canvas2dRenderer`, `sharedRenderer`, `autoRenderer`, `createChartRenderContext`, `Canvas2DUnavailableError`, and the `ChartRenderContext` type are exports of `blazeplot`; the option also takes the names, so most code can write `renderer: "canvas2d"` or `renderer: "shared"` with no import.
- `chart.renderer` reports `"shared"` instead of `"webgl2-shared"`. `ChartRendererKind` is now `RendererName` (`"webgl2" | "canvas2d" | "shared"`).
- A `renderer` value that is not one of the names or a factory throws a `TypeError` that lists the valid names. `"canvas2d"` is accepted (it used to be rejected).

## Changes

- `chart.rendererInfo` (`name`, `requested`, `fallbackFrom`, `capabilities`), the read-only `ctx.renderer` for plugins, and a reserved `rendererchange` event that nothing emits yet. `RendererChoice`, `RendererName`, `ChartRendererInfo`, and `ChartRendererCapabilities` are exported types.
- `createLinkedCharts({ renderer })` takes the same names and factories.
- Canvas 2D is a first-class, stable engine: the feature set is covered by semver, pixel-level output between engines and releases is not (see [API stability](https://github.com/Federicocervelli/blazeplot/blob/v1/docs/stability.md)).
- Plugin layers follow the chart's engine. New experimental `ctx.unstable.createRenderSurface(canvas)` (`ChartRenderSurface`: `beginFrame`, `fillRects`, `endFrame`, `isLost`, `setLossListener`, `dispose`). The flame graph plugin now draws its rectangles through it: it no longer opens a second WebGL context, follows the `renderer` option, joins the shared context, and its entry shrank by about 4.7 KB.
- Context loss and restore are reported by every engine. Plugins' `onContextLost` and `onContextRestored` now also run for Canvas 2D in browsers that fire canvas `contextlost` and `contextrestored`; `ctx.unstable.getWebGLContext()` stays `null` on Canvas 2D and the shared engine.

## Fixes

- Canvas 2D filled area series across gaps (non-finite Y) instead of breaking the fill at them like WebGL does. Found by the new cross-engine visual comparison.

## Tooling

- One behavior contract suite runs against all three engines; the UI suites run on Canvas 2D, WebGL2, and the shared engine over canvas doubles.
- The visual suite compares the Canvas 2D and shared renders with the WebGL2 render of the same case (`scripts/cross-engine.ts`); a Canvas 2D performance gate (`bun run bench:gate:canvas2d`) has its own thresholds; the interaction, axe, and stability suites run on Canvas 2D; the Firefox and WebKit smoke tests run a Canvas 2D pass.

## Bundle

- The chart-only import graph (`index` + the Chart chunk + theme) grew from about 182.6 KB to 196.9 KB (+14.3 KB, +7.8%) because Canvas 2D and the shared context now ship with the default renderer; a new combined budget guards it. The flame graph plugin entry went from 22.1 KB to 17.4 KB, and the two renderer subpath entries are gone.
