# BlazePlot v1.0.0-rc.7

Seventh 1.0 release candidate. Follow-ups to rc.6: plugin-owned CSS, sub-millisecond time axes, a faster many-series line path, new browser coverage, and real-GPU benchmark numbers (including Canvas 2D). Install with `npm install blazeplot@rc`.

## Changes

- Plugin forced-colors CSS moved out of the core stylesheet into each plugin (one deduped `<style>` per plugin per document, removed when the last chart disposes). Chart-only bundles ship none of it. As a side effect, plugin forced-colors rules now apply even with `accessibility: false`. Tooltip and crosshair share one marker-pool and long-press helper.
- Time axes zoomed below 1 ms now get proper sub-millisecond ticks and fractional-second labels.
- Y and Y2 axis titles are centered on the plot area (and a rotation offset is fixed).
- `touchPan: "two-finger"` no longer shows the "use two fingers" hint on the pointercancel that ends a two-finger gesture.
- Fixed global `getComputedStyle` / `matchMedia` use in screenshot and theme code, so charts in iframes and popup windows use their own window.
- Website linked-chart panels no longer need `boxZoom: false`.

## Performance

- Raw line extraction reads datasets in bulk instead of per-sample calls: the 100-series pan scenario drops from about 25 ms to about 7 ms per frame on a real GPU. Other scenarios are unchanged.
- Real-GPU (RX 9070, ANGLE/D3D11) benchmark results are published, including a Canvas 2D column. Level with rc.5 on the existing scenarios.

## Tooling

- `BLAZEPLOT_REAL_GPU=1` and `BLAZEPLOT_CHROME_FLAGS` let the browser scripts run on a real GPU. New bench scenarios: `many-series-100x20k-pan`, `scatter-1m-sampled-pan`. New browser tests: screenshot overlays and first-frame screenshot, annotations on log/symlog/reversed axes, charts in iframes, linked charts on the website.

## Shared context numbers

- A shared WebGL context never loses contexts and costs about 0.3 ms per chart per redraw; 60 fps holds to about 50 charts redrawing every frame. Below the browser's per-page context cap, per-chart contexts are about 3x cheaper per frame, so `createLinkedCharts` stays on per-chart contexts and `sharedRenderer()` stays opt-in. Details in `docs/performance-recipes.md`.

## Known limitations

- One-finger page scrolling with `touchPan: "two-finger"` is only verified through touch emulation, not on a physical phone.
