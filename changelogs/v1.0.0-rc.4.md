# BlazePlot v1.0.0-rc.4

Fourth 1.0 release candidate. A bug-fix release for forced-colors (high contrast) mode, found by a new real-browser test. No API changes since rc.3. Install with `npm install blazeplot@rc`.

## Fixes

- Forced colors: tooltip and crosshair swatches and the inspection marker keep their series color instead of turning into plain system-color squares.
- Forced colors: the navigator window is outlined instead of filled, so it no longer tints the whole overview.
- Forced colors: system colors used for the background, text, and series are resolved as opaque. Chromium on Linux reports `Highlight` with 0.8 alpha, which drew the first series translucent.

## Docs and tests

- New real-browser forced-colors check (`bun run test:forced-colors`, part of `test:browser`): emulates `forced-colors: active` over CDP, checks system colors, pixel visibility, and contrast, then checks that turning it off restores the theme without a reload.
- `docs/accessibility.md` now states how accessibility is verified, and the manual screen reader steps are a guide for app developers rather than a release requirement.
