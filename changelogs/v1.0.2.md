# BlazePlot v1.0.2

A performance release. Dense charts pan and stream 1.6 to 1.8 times faster on both rendering engines, and large static charts and mount/destroy cycles are quicker. The public API is unchanged.

The performance notes in 1.0.1 listed changes that did not move the benchmarks when measured. The numbers below are measured: the same machine, browser and benchmark scenarios, 1.0.1 against this release.

## Faster

Real GPU (AMD Radeon RX 9070), Chrome 154, median of 7 fresh-page runs. FPS is frames per second, higher is better.

| Scenario | Engine | 1.0.1 | 1.0.2 |
|---|---|---:|---:|
| 1M-point line, pan (FPS) | WebGL | 677 | 1104 |
| 1M-point line, pan (FPS) | Canvas 2D | 568 | 924 |
| 1M-point line, live stream (FPS) | WebGL | 660 | 1086 |
| 1M-point line, live stream (FPS) | Canvas 2D | 557 | 928 |
| Two Y axes, 1M points, pan (FPS) | WebGL | 386 | 668 |
| Two Y axes, 1M points, pan (FPS) | Canvas 2D | 320 | 536 |
| 10 series of 100k points, pan (FPS) | WebGL | 158 | 299 |
| 10 series of 100k points, pan (FPS) | Canvas 2D | 113 | 203 |
| 100k bars, pan (FPS) | Canvas 2D | 746 | 1127 |
| 1M-point line, first render (ms) | WebGL | 15.0 | 12.1 |
| 1M-point line, first render (ms) | Canvas 2D | 12.6 | 10.2 |
| Mount, first frame and destroy (ms) | WebGL | 1.80 | 1.23 |
| Mount, first frame and destroy (ms) | Canvas 2D | 2.20 | 1.50 |

- Dense min/max extraction is the main change. Dense views read their per-pixel min/max buckets in bulk instead of one tree query per bucket, and the per-frame path allocates far less.
- The Canvas 2D engine merges rectangles that fall in the same pixel column and builds each polyline in two passes, with identical pixels.
- Large static series build their min/max summary level by level, which speeds up the first render of a million-point chart.
- Mounting and destroying many charts reads layout once per frame instead of once per chart, and creates fewer tick-label styles.
- JS heap growth while panning a million-point line dropped from 0.32 to 0.06 MiB on WebGL and to 0.12 MiB on Canvas 2D.

Hover latency, WebGL context creation and the first chart on a cold page are unchanged. uPlot is still faster on those; the new [Benchmarks](https://blazeplot.cervelli.dev/docs/benchmarks) page lists them.

## Documentation

- The Benchmarks page is now one table of the seven most relevant scenarios with a line on where uPlot is faster. Every metric stays on a separate Benchmark results page.
- Removed filler from the guides, the maintainer docs and the README, and fixed a broken link in the troubleshooting table.
- The README performance section shows one concrete result instead of a win count.

## Tooling

- `bun run bench:ab` compares two checkouts on the real GPU with interleaved runs and a significance test; `--core` runs the seven scenarios that matter.
- The benchmark's heap-soak metric no longer counts the harness's own per-frame samples as heap growth.
